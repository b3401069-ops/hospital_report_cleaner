# 醫院癌症報表清洗器

醫院癌症報表清洗器。把 `raw/` 裡多個 Excel 報表整理成 `output/cleaned_reports.xlsx`，並產生標準化資料、病人清單、中文摘要、對照規則待確認清單與 TNM／期別檢查。

請先看這份短版操作說明：

[使用說明.md](使用說明.md)

## 最短使用方法

1. 解壓縮專案資料夾。
2. 第一次使用先按兩下 `安裝套件.bat`。
3. 把要清洗的 Excel 報表放進 `raw/`。
4. 按兩下 `清洗報表.bat`。
5. 到 `output/cleaned_reports.xlsx` 查看結果。
6. 打開後會停在 `病人查詢`，在黃色欄位輸入完整病歷號。比較多人時切換到 `病人總表`。
7. 如果想先檢查電腦能不能跑，按兩下 `檢查環境.bat`。

## Windows 批次檔

- `安裝套件.bat`：安裝或更新 Python 套件，完成後執行環境檢查。
- `檢查環境.bat`：檢查 Python、套件、資料夾、對照規則 CSV、`output/` 寫入權限。
- `清洗報表.bat`：產生 `output/cleaned_reports.xlsx`。
- `匯出待確認.bat`：產生 `output/pending_*_mapping.csv`，供人工確認新藥物、醫令碼或 TNM 期別。
- `套用確認.bat`：把已確認的待確認規則套回 `mapping/*.csv`。

如果電腦顯示找不到 Python，請先安裝 Python 3：
https://www.python.org/downloads/

## 輸出工作表

`output/cleaned_reports.xlsx` 會包含：

- `使用說明`：第一頁，說明總表位置、各分頁用途與本次品質計數。
- `病人查詢`：輸入完整病歷號，一頁看姓名、癌別、期別、治療、藥物與回診摘要。保留病歷號前面的 0；查無資料或同號多列時會明確提示。
- `病人總表`：日常主要查閱表，以病歷號優先合併為一人一列；只保留常用欄位，包含癌別、TNM／期別、治療、藥物、回診日與資料提醒。
- `統計摘要`：依癌別、期別、性別、年齡與治療彙總。
- `月趨勢`：近五年每月一列；新診斷依診斷日，治療事件依實際治療日統計。
- `治療藥物明細`：已分類的治療或用藥事件，可查日期、治療類型、醫令碼、藥物／術式名稱與來源報表；相同事件會合併並保留 `紀錄筆數`。
- `抽查清單`：自動挑選 30 位多癌別、TNM 待確認、多治療／多藥物或關鍵資料缺漏的病人，供同事對照院內系統。
- `病人期別待確認`：以個案與 TNM 情境列出缺期別資料，也納入缺少 TNM 的情況；人工結果另填 `review/病人期別確認.xlsx`。個案識別不足時須先補正來源。
- `ICD10待確認`、`TNM期別待確認`、`藥物待確認`、`治療醫令待確認`：需要人工檢視的資料。
- `cleaned_data`、`standardized_data`、`patient_master`、`patient_list`、`stage_review`：工程與稽核底稿，預設隱藏，資料仍完整保留。

`病人總表` 的治療欄顯示「有」，代表來源資料中找到該治療紀錄；空白只代表目前來源沒有找到，不等於確認未接受治療。

總表把手術、放療、化療、標靶等分成獨立欄，能用欄名下拉選單同時篩選癌別、期別、醫師與治療。姓名和病歷號固定在左側；診斷、TNM、藥物等長文字放在右側收合欄，可按上方「＋」展開，或到 `病人查詢` 閱讀。最終期別保留來源的多個值，不把多癌別擅自簡化成單一期別。

查詢頁使用 Excel 一般公式，不需啟用巨集。輸入後由 Excel 自動計算；靜態檔案預覽可能不支援互動查詢。點「前往這位病人的總表列」可跳到對應列；治療藥物明細請再以病歷號篩選。查詢輸入只用於本次閱讀，重新清洗會產生新的空白查詢頁。

同一病人若有多個癌症個案、不同 TNM 或多種藥物，總表會用摘要保留；完整的多次治療與用藥歷程請看 `治療藥物明細`。`資料提醒` 會以黃色標出癌別、診斷日、回診日、日期先後異常或未來診斷日，但不代表醫療判定有誤。`最後回診日` 只採來源中明確的追蹤／回診欄位，`最後資料日期` 則包含治療與醫令日期，兩者用途不同。

`治療藥物明細` 只顯示已由規則分類為治療的醫令；尚未分類的新藥物或醫令請查看黃色待確認分頁。若 `紀錄筆數` 大於 1，表示相同病人、日期、治療與醫令在來源中重複出現，報表已合併顯示但沒有遺失原始筆數。

檔名含 `醫令碼` 或 `對照表` 的對照參考活頁簿會自動略過。內容完全相同的來源報表也只處理一次並顯示警告，避免重複計算；若被略過的檔案原本應有不同資料，請先回頭修正來源檔。

`抽查清單` 的 `人工確認結果` 可選擇「正確、需修正、待確認」。這份清單是品質抽查工具，不會取代醫療端判讀。

已確認的 AJCC8 TNM 大分期規則與限制記錄在 [docs/AJCC8規則.md](docs/AJCC8規則.md)。乳癌、攝護腺癌或 TNM 含 `X` 等無法只靠目前欄位安全判定者，不會自動填期別。

## 病人期別確認（個案補正）

1. 執行 `清洗報表.bat`，或請 AI agent 執行本專案的 `python -m report_cleaner.cli`。
2. 在報表的 `病人期別待確認` 查看病人、癌症個案、TNM 與來源。實際填寫請開啟 **`review/病人期別確認.xlsx`** 的 `個案確認`，不要直接改輸出總表。
3. 核對院內紀錄後，只填黃色欄位：`確認期別`、`分期類別`、`確認依據`、`確認人`、`確認日期`，再將 `確認狀態` 選為 `已確認`。不知道的維持待確認，不必一次填完。
4. 儲存並關閉確認檔，重新執行一次清洗。程式會讀回確認結果、更新總表及待確認清單；不需再按 `套用確認.bat`。

這是程式每次執行的固定流程，不靠 AI 的對話記憶。只補病人識別、個案、癌別、診斷日與臨床／病理 TNM 全部相符的空白期別，不會把某位病人的答案變成所有人共用的 TNM 規則。已有期別不覆蓋；若與確認值不同，確認檔的 `本次狀態` 會提示核對。識別欄不要修改或複製整列。

總表的 `期別資料狀態` 與統計摘要會區分缺期別、部分資料待確認、含個案人工確認及已有期別但未核驗。已有期別不代表已完成醫療核驗，待確認筆數也不等於病人人數。這個流程不會自動判定 AJCC 分期。

`review/` 是持續保存的人工確認資料，不是可刪除的輸出暫存。重新清洗會保留已填內容及本批未出現的舊個案，並備份上一版確認檔。搬電腦或換 agent 時，須使用新版程式並保留同一份 `review/`；其中含病人資料，禁止上傳 GitHub。

## 對照規則確認流程

每次清洗只處理 `raw/` 的來源；`review/` 不會補回未提供的病人或治療歷程。五年查閱版是原成品的閱讀副本，重洗完整五年資料仍需備齊該期間來源，不能用較短期間資料替代。

**以下是管理者維護共用規則的流程，不適合用來補正單一病人的期別。** TNM 規則需要確認其可適用於整個規則範圍；不能只根據一位病人的結果就新增。

當新報表出現程式還不認識的藥物、治療醫令碼或 TNM／期別組合時：

1. 按 `匯出待確認.bat`。
2. 打開 `output/pending_drug_treatment_mapping.csv`、`output/pending_order_treatment_mapping.csv`、`output/pending_tnm_stage_mapping.csv`。
3. 由 Codex 或醫療端確認要新增的欄位，例如 `treatment_type`、`order_code`、`name_pattern`、`final_stage`。
4. 確認完成後按 `套用確認.bat`。
5. 再按 `清洗報表.bat` 重新產生報表。

## 資料安全

- `raw/`、`output/` 和 `review/` 會被 `.gitignore` 排除，不應上傳 GitHub。
- 請不要把真實病人報表、輸出 workbook、截圖或含病歷號的檔案 commit。
- `mapping/*.csv` 可以上傳，內容是欄位、ICD10、TNM、藥物與治療醫令碼規則。
- `mapping/*.csv` 使用 UTF-8 with BOM，方便 Windows Excel 開啟繁體中文。

## 專案結構

- `raw/`：放原始 Excel 報表，不上傳 GitHub。
- `mapping/`：欄位與分類規則，可維護、可上傳。
- `output/`：產生的報表與待確認對照規則，不上傳 GitHub。
- `review/`：持續保存的病人期別確認與上一版備份，不上傳 GitHub；換電腦須一起移轉。
- `src/report_cleaner/`：清洗程式。
- `tests/`：自動測試。
